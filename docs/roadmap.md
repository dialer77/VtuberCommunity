# VMOA 로드맵 · 인수인계

새 세션은 이 문서부터 읽고 시작합니다. 현재 상태, 남은 설정, 다음 작업 순서, 이미 정한 결정, 작업 규칙을 모았습니다.

기준일: 2026-11-13

## 1. 한눈에 보기

**버모아(VMOA)** — https://vmoa.live · 한국 버튜버 허브. 치지직·SOOP 실시간 방송(LIVE), 랭킹, 신규 데뷔, 이슈 타임라인, 사이트 안 유튜브 플레이어, 최애·방송 시작 알림.

| 구성 | 내용 |
| --- | --- |
| `web/` | Next.js 16 · React 19, Vercel(`vtuber-community`)에 `main` 푸시 시 자동 배포 |
| `server/` | Node 24 + Fastify(tsx). 배포 PC(Windows 10)에서 실행, Cloudflare Tunnel 로 `https://api.vmoa.live` |
| 수집 데이터 | SQLite `server/data/vmoa.db` (다시 쌓을 수 있음) |
| 사용자 데이터 | Postgres `USER_DATABASE_URL` (지금은 배포 PC 의 Postgres, 나중에 외부 DB 로 이전) |
| `app/` | Flutter 스타터 (미빌드, 현재 작업 대상 아님) |

**배포 흐름**: `main` 에 푸시하면 Vercel 이 웹을 배포하고, 배포 PC 감독 스크립트가 1분마다 확인해 `server/**` 가 바뀌었으면 서버를 재시작합니다(패키지가 바뀌면 `npm ci` 포함). 서버 반영 확인은 https://api.vmoa.live/health 의 `version`(커밋 해시)으로 합니다.

## 2. 지금 상태

### 완료
- LIVE: 치지직·SOOP 수집, 태그 바(소속사·컨셉·콘텐츠), 버튜버 프로필 페이지
- 랭킹: 실시간·오늘·주간·월간 (`channel_daily` 일별 집계)
- 신규 데뷔: 감지 + 웹 수집(Claude), 이번 달·1개월·3개월 탭
- 이슈 타임라인: 3시간마다 Claude 웹 검색으로 정리, 출처 표시
- 사이트 안 유튜브 플레이어: 크게 보기·미니 플레이어, 페이지 이동해도 재생 유지
- 커뮤니티 기반: 구글 로그인, 최애, 방송 시작 웹 푸시, 내 페이지(`/me`), 탈퇴, 이용약관·개인정보처리방침
- 소속사 필터: 소속사 명단(roster) 기반 판정 (`server/src/tags/roster.ts`, `roster-seed.json`)
- V코인(`/coins`): 비공식 베타로 메뉴에서 숨김
- 유튜브 공식 채널 연동 (2단계): 채널 매핑(치지직 `socialLinks`·SOOP `link` 의 유튜브 링크로 자동 추정 + 운영자 확정 `deploy\windows\youtube.ps1`), 프로필 "공식 영상" 탭(RSS + `videos.list`, 사이트 안 재생), 유튜브 라이브 감지(LIVE 목록·프로필에만, 홈 합계·랭킹·데뷔 감지 제외), 30일 갱신·정리. 코드 `server/src/youtube/`, 운영 `docs/youtube-api.md` 3장
- 키리누키 참여 (4단계, 로그인 기반 — 사용자 DB·구글 로그인 설정 후 켜짐): 클립 좋아요(`/clips?sort=likes` 좋아요순), 내 재생목록(만들기·담기·이름 바꾸기·전체 재생 — 공식 임베드 `playlist` 매개변수), '어떤 순간' 태그 투표(찬반 2표 차이로 분류에 반영), 내 페이지 "내 재생목록"·"좋아요한 클립". 사용자 DB `userdb/clips.ts`, 합계는 수집 DB 에 복사
- 키리누키 수집·분류 (3단계): 키리누키 채널 발견(`search.list` 하루 20회, 채널 ID 만) → RSS 추적 → Claude 헤드리스 분류(누가·무엇을·어떤 순간·한 줄 요약, RSS 제목·설명만 입력) → 비슷한 클립(같은 버튜버·다른 버튜버). `/clips` 모음·태그별, `/clips/<ID>` 상세, 프로필 "키리누키" 탭(특징 태그). 코드 `server/src/clips/`, 운영 `deploy\windows\clips.ps1`, `docs/youtube-api.md` 4장
- 버튜버 검색 (`/search`, 2026-11-11): 방송 중이 아니어도 수집 DB 의 채널 전체를 이름·예전 이름(일별 집계)·확정 목록 이름·유튜브 채널명·초성(`ㅅㅌ`)·`#태그` 로 검색. 태그 칩(소속사·컨셉·콘텐츠, 여러 개 = 모두 만족), 태그 이름을 그대로 쓰면 그 태그 버튜버도 함께, 검색어 없으면 최근 30일 많이 본 순. 헤더 검색창(좁은 화면은 아이콘), 프로필의 태그를 누르면 같은 태그 버튜버 목록. 코드 `server/src/search.ts`(메모리 색인 10분 갱신), `web/src/components/search/`
- 유튜브 전용 버튜버 (2026-11-13): 치지직·SOOP 채널 없이 유튜브에서 활동하는 버튜버를 `yt_vtubers` 로 따로 관리. 7일마다 Claude 웹 수집(한국 유튜브 버튜버 + 키리누키에 나오는데 모르는 버튜버, 해외 포함) + 데뷔 소식의 유튜브 채널 + 운영자 `youtube.ps1 vtuber-add` → API 로 채널 확인 후 등록. 검색(이름·별칭·유튜브 채널명·소속), 프로필 `/vtuber/youtube/UC…`(공식 영상·노래·키리누키, 방송 통계 대신 노래·클립 수), 키리누키 출연 연결(새 클립은 분류 후보, 예전 클립은 RSS 제목·요약에 이름 전체), 키리누키 채널 찾기 대상(한국어만), 유튜브 라이브(한국어만 LIVE 목록, 해외는 프로필·검색에만). 나중에 치지직·SOOP 버튜버의 공식 채널로 연결되면 자동으로 빠짐. 코드 `server/src/youtube/vtubers.ts`, 운영 `docs/youtube-api.md` 5장
- 노래 모음 (2026-11-13): 공식 채널 영상 중 제목에 커버·오리지널 표기가 있는 노래. RSS(새 노래) + 업로드 목록 한 번 훑기(예전 노래) → videos.list 로 길이(1~15분)·공개 확인, 20일마다 갱신. `/songs`(전체·커버·오리지널·검색·전체 재생), 프로필 "노래" 탭, 홈 "새로 올라온 노래", 통합 검색 노래 결과, 메뉴 "노래". 코드 `server/src/youtube/songs.ts`, `web/src/components/song-card.tsx`, 운영 `docs/youtube-api.md` 6장
- 애드센스 연결 (2026-11-12): Vercel `NEXT_PUBLIC_ADSENSE_CLIENT`(공개 값) → `<head>` async 스크립트, `google-adsense-account` 메타 태그, `/ads.txt`. 광고 칸은 `NEXT_PUBLIC_ADSENSE_SLOT_HOME_MID`·`_ISSUE_BOTTOM`(광고 단위 숫자 ID)이 있을 때만 그림 (`web/src/components/ad-slot.tsx`)
- 검색 노출 보강 (2026-11-12): 사이트맵에 버튜버 프로필(방송 3회 이상 또는 최근 90일 방송, `/api/sitemap`)·키리누키 상세 추가, 프로필 제목 `이름 (플랫폼) 방송 기록·클립`·설명문(소속사·주로 하는 방송·최근 방송일·기록, 방송 제목은 넣지 않음)·canonical·JSON-LD(ProfilePage), 기준 미달 프로필 noindex (`web/src/lib/seo.ts` — 서버 기준과 같게 유지), 프로필 "주로 하는 방송" 요약(카테고리·제목 키워드, 실사·코스프레 같은 민감한 방송 종류는 일부러 제외). 프로필 통계·방송 기록은 스냅샷 보관(7일) 이후에도 방송별 태그 기록·일별 집계로 이어서 보여 줌 (오래된 방송은 날짜·마지막 제목·최고 동접만). 치지직 성인(19세) 방송은 썸네일을 받지 않음 (광고 페이지 안전)

### 코드는 배포됐고, 사용자가 설정해야 켜지는 것
배포 PC 작업은 RDP 로 사용자가 직접 실행합니다.

- [x] **YouTube API 키 등록** (2026-11-10 완료): 배포 PC `server\.env` 의 `YOUTUBE_API_KEY`. 교체할 때는 바탕화면 `youtube-key.txt` → `deploy\windows\setup-youtube.ps1` (`docs/youtube-api.md`). 키가 있으므로 공식 채널 연동이 자동으로 켜져 있음 (하루 보통 2,000단위 아래, 예산 8,000)
- [ ] **유튜브 매핑 정리**: 배포 후 1~2시간이면 상위 200명 1회차가 끝남. `deploy\windows\youtube.ps1 pending` 으로 후보가 여럿·다시보기만·공용 채널인 버튜버를 `set`/`none` 으로 정리, `list nolink` 중 공식 채널이 있는 버튜버는 `set` (개발 PC 시험 기준 190명 중 확인필요 13명, 링크없음 41명)
- [ ] **키리누키 확인** (배포 후 하루쯤): `deploy\windows\clips.ps1 status` 로 채널·클립이 쌓이는지, `recent 30` 으로 분류가 맞는지 보고, 클립 채널이 아닌 것은 `block`. 분류는 Claude 구독 토큰을 쓰므로 **이슈 수집 토큰 교체 전에는 실패할 수 있음** (30분 뒤 자동 재시도). 서버 `.env` 에 `ISSUES_ENABLED=1` 이 없으면 `CLIPS_ENABLED=1` 을 넣어야 켜짐
- [ ] **사용자 DB**: `deploy\windows\setup-userdb.ps1` (`docs/user-accounts.md` 1단계). 최애·알림에 더해 4단계(좋아요·재생목록·태그 투표)도 이게 있어야 켜짐
- [ ] **구글 로그인**: Google OAuth 클라이언트 발급 → Vercel 환경변수 5개 → 재배포 (`docs/user-accounts.md` 2·3단계)
- [ ] **애드센스 검토**: 애드센스 화면에서 사이트 소유권 확인(코드 스니펫·메타 태그·ads.txt 모두 적용됨) → 검토 요청. 승인되면 자동 광고를 켜거나, 광고 단위를 만들어 숫자 ID 를 Vercel `NEXT_PUBLIC_ADSENSE_SLOT_*` 에 넣고 재배포
- [ ] **유튜브 전용 버튜버 확인** (배포 후 일주일쯤): 첫 웹 수집은 배포 직후 Claude 작업 순서가 오면 돈다(이슈·데뷔·클립 분류 다음). `youtube.ps1 vtubers` 로 목록을 보고 버튜버가 아니거나 잘못 찾은 채널은 `vtuber-block`, 아는데 빠진 버튜버는 `vtuber-add`. `youtube.ps1 songs` 로 노래가 쌓이는지 (처음 훑기는 며칠)
- [ ] **이슈 수집 토큰 교체**: 사용자가 Claude 계정을 바꿀 예정이라 새 계정으로 다시 발급 — `deploy\windows\setup-issues.ps1 -RenewToken`

- 버튜버 이름 별칭(예: "리코" → 유즈하 리코) 사전 (태그 투표는 4단계에서 화면 분류에 반영됨)
- 키리누키 채널 발견을 검색 외에 영상 설명의 원본 링크로 넓히기

처음 계획 (기록용):
- 목표: "A 클립이 재밌다 → 같은 버튜버의 비슷한 클립 / 다른 버튜버의 비슷한 클립"을 찾아 주기
- 키리누키 채널 발견: `search.list`(하루 100회 별도 한도)로 버튜버 이름 검색 → 채널을 등록해 두고 이후 새 영상은 RSS 로 추적
- 분류: 누가 / 무엇을 / 어떤 순간 / 한 줄 요약 태그. Claude 헤드리스(구독)로 생성
  - **정책 주의**: API 로 받은 데이터로 파생 데이터를 만들면 안 됨(III.E.4.h). 분류 입력은 RSS 제목·설명과 사용자 참여(투표·태그)로 하고, 화면에는 "버모아 분류"로 표시
- 비슷한 클립: 태그 + 로컬 임베딩
- 주제별 모음 페이지, 버튜버별 특징 태그
- 범위: 상위 100~200명부터

### 4단계 — 키리누키 참여 (로그인 기반) ✅ 완료 (2026-11-11)
좋아요, 내 재생목록, 태그 투표. 사용자 DB·구글 로그인 설정이 끝나면 켜짐

남은 것 (필요해지면):
- 재생목록 순서 바꾸기 (지금은 담은 순서), 카드에서 바로 좋아요
- 태그 투표 반영 기준(2표)을 이용자 수에 맞춰 조정, 도배 방지는 6단계 운영 도구와 함께

### ★ 클립 추천 트랙 — 최우선 (2026-11-12 결정)

목표: 유튜브 추천과 다른 **버모아만의 키리누키 추천**. 버튜버 문화에 맞춘 분류(누가·무엇을·어떤 순간·어떤 사건)와 관계(같은 방송·같은 사건·자주 합방하는 사이)로 "왜 이 클립인지" 설명할 수 있는 추천을 하고, 사용자가 추천을 직접 조절할 수 있게 한다.

2026-11-12 운영 기준 출발점: 보이는 클립 2,222개. 분류 = 카테고리 1개 + 순간(12종, 여러 개) + 주제(자유 글) + 한 줄 요약 + 출연 버튜버. 비슷한 클립 = 분류 + 제목·요약 글자 2-gram (`server/src/clips/similar.ts`). 약점: 순간 '웃음'이 83%(1,841개)라 구별력이 없음, 주제 표기가 제각각("마크"/"마인크래프트"), 원본 방송·사건 연결 없음, 사용자 신호 없음(로그인 전).

**R1. 분류 품질 — 추천의 재료** ✅ 완료 (2026-11-12)
- 구현: `server/src/clips/classify.ts`(분류 2판 + 보강 모드), `topics.ts`(주제 별칭), `source.ts`(원본 링크), 저장 열 `primary_moment`·`event`·`source_url`·`source_key`·`source_date`·`class_ver`, 표 `clip_topic_alias`
- 개발 PC 실제 시험(실제 RSS 60개 + 실제 Claude): 새 분류 12개 중 대표 순간 '웃음' 2개(기존 83%), 원본 방송 7개, 서로 다른 채널의 클립 2개가 같은 치지직 다시보기·같은 사건으로 묶임. 설명에 방송 링크가 있는 클립 45/60
- 기존 클립: 새 클립이 없을 때 30분마다 80개씩 보강 (`CLIPS_ENRICH_BATCH`). 설명이 이미 지워져 원본 방송은 새 클립부터. 제목은 videos.list 로 바뀐 적 없는 클립만 재료로 씀
- 운영: `clips.ps1 status`(classVersion = 보강 진행), `topics`·`alias <별칭> <정식 이름>`·`events`, `issues.ps1 interval 720`(이슈 주기 → 12시간)
- 남은 것: 사건 이름이 클립 하나짜리로도 붙는 경향 — 운영 데이터(`clips.ps1 events`)를 보고 R2 에서 2개 이상 묶인 사건만 쓰거나 프롬프트 조정
- 대표 순간 1개(`primaryMoment`) + 보조 순간 최대 2개. '웃음'은 다른 순간이 없을 때만. 필요하면 순간 어휘 세분화(드립·몸개그 등)
- 주제(게임·콘텐츠) 이름 사전: 별칭 → 정식 이름 (Claude 제안 + 운영자 확정)
- 원본 방송 연결: 클립 설명의 원본 링크(치지직·SOOP 다시보기, 유튜브)·방송 날짜 → `source` (같은 방송의 다른 클립, 원본 다시보기 링크)
- 사건·밈 키: 같은 일을 다룬 클립을 묶는 짧은 이름 ("김웅 고발" 등). 채널이 달라도 같은 사건이면 같은 키
- 기존 클립 재분류 배치 (Claude 구독 사용량은 이슈 수집 주기를 줄여 확보)
- 정책: 분류 입력은 지금처럼 RSS 제목·설명만 (API 데이터로 파생 데이터 금지), YouTube 조회수는 순위·합산에 쓰지 않고 버모아 자체 신호(좋아요·투표)만

**R2. 설명 가능한 추천 묶음** (클립 상세·프로필) ✅ 완료 (2026-11-13)
- 구현: `server/src/clips/recommend.ts` → 클립 상세 API `bundles` (예전 `sameVtuber`·`otherVtuber` 도 함께), 웹 `web/src/components/rec-bundles.tsx`(카드마다 추천 이유)
- 묶음 순서: ① 같은 방송의 다른 장면 ② 같은 사건 ③ 같은 버튜버의 비슷한 순간(모자라면 인기·최신으로 채움) ④ 다른 버튜버의 비슷한 장면(같은 게임이거나 같은 대표 순간, 웃음·일반 주제 '저챗' 등은 근거로 안 씀) ⑤ 자주 함께 나오는 버튜버(클립 공동 출연 2회 이상)
- 한 클립은 한 묶음에만, 한 키리누키 채널은 묶음당 2개(같은 방송 4·같은 사건 3)까지, 제목이 거의 같은 재업로드는 하나만, 가산점은 버모아 좋아요·최신만
- 프로필 키리누키 탭: "클립에 자주 함께 나오는 버튜버"
- 시험: 운영 클립 2,565개 분류 결과로 만든 DB 에서 묶음 계산 평균 9ms, 중복·채널 독차지 없음
- 묶음: ① 같은 방송의 다른 장면 ② 같은 사건·밈의 다른 시점 ③ 같은 버튜버·같은 결의 순간 ④ 다른 버튜버·같은 게임·같은 순간 ⑤ 자주 같이 나오는 버튜버(클립 공동 출연으로 만든 합방 관계) ⑥ 이 클립을 좋아한 사람이 좋아한 클립(로그인 사용자 생긴 뒤)
- 카드마다 추천 이유 표시 ("같은 방송", "봉누도2 · 레전드", "자주 합방하는 OO")
- 다양성(한 채널·한 사건이 목록을 독차지하지 않게), 재업로드·같은 장면 중복 제거, 최신·좋아요 반영
- 클립이 5천 개 이상 쌓이고 결과가 부족하면 로컬 임베딩(multilingual-e5 ONNX) 추가

**R3. 측정** (R2 와 함께) ✅ 완료 (2026-11-13)
- 묶음이 화면에 40% 보이면 노출, 썸네일 재생 = 재생, 제목 = 열기. 날짜·묶음별 합계만 저장(`rec_stats`, 사용자·IP 없음). 웹 `/api/rec` → 백엔드 `/api/rec/events`
- 보기: `clips.ps1 recstats [일수]` — 묶음별 노출·열기·재생·클릭률. 몇 주 쌓이면 클릭률을 보고 묶음 순서·가중치 조정
- 추천 묶음별 노출·클릭을 익명으로 집계 (개인정보 없음) → 묶음별 클릭률로 가중치 조정. `clips.ps1` 또는 관리 화면에서 확인

**이어보기·본 기록** ✅ 완료 (2026-11-13, R5 일부를 로그인 없이 먼저)
- 전역 플레이어를 유튜브 공식 IFrame API 로 바꿈(`web/src/components/player/`). 막힌 환경에서는 예전 일반 임베드로 재생
- 키리누키가 끝나면 이어보기 후보(`/api/clips/:id/next` = 추천 묶음 순서, 같은 방송은 이 클립 다음 장면 먼저) 중 안 본 첫 클립을 재생. 플레이어에 "다음: 제목 · 이유", [다음 ▶], 이어보기 켬/끔(브라우저에 기억). 내 재생목록은 순서대로
- 본 기록: 30초(짧으면 절반) 이상 보거나 끝까지 본 영상을 이 브라우저 localStorage 에만 저장(`web/src/lib/watched.ts`, 최대 1,000개, 서버로 안 보냄). 카드에 "봤어요", 추천 묶음은 안 본 클립 먼저(서버는 묶음당 12개까지 보내고 화면은 8개)
- 시험: Orca 브라우저 실제 재생 — 30초 지나 본 기록 저장, 쇼츠가 끝나자 안 본 다음 클립으로 자동 재생, 본 클립 건너뜀. 창 없는 Chrome 은 유튜브가 재생되지 않아 끝 이벤트 시험 불가
- 남은 것: 로그인 사용자는 본 기록을 사용자 DB 에 동기화(기기 간), 본 기록을 추천 점수에도 반영(많이 본 게임·순간 가산) → R5

**R4. 탐색 페이지** (검색 유입 + 입문)
- 버튜버 입문 모음 "OO 처음이라면" (좋아요·레전드·다양성 기준)
- 사건·밈 페이지(시간순), 게임별 모음("봉누도2 클립"), 합방 조합 페이지("치치 × 쿠온 레이")
- 주간 베스트 클립 (투표와 연결)

**R5. 내 맞춤 추천·사용자 조절** ✅ 완료 (2026-11-13)
- 내 취향 추천 (`/clips` 맨 위): 본 기록(최근일수록 무겁게)·좋아요에서 자주 본 버튜버(주인공만 강하게, 조연은 약하게)·게임(일반 주제 제외)·대표 순간을 뽑아 안 본 클립을 이유와 함께. 한 채널 2개·한 버튜버 4개·같은 이유 5개까지. 기록 없으면 요즘 인기. 서버 `server/src/clips/foryou.ts`(`POST /api/clips/for-you`, 받은 기록은 계산에만 쓰고 저장 안 함), 웹 `web/src/components/for-you.tsx`
- 직접 조절: 카드 ⋯ 메뉴(관심 없음·이 채널 숨기기·이 주제 덜 보기, 되돌리기 덮개), 취향 설정 패널(좋아하는 순간·숨긴 채널·덜 볼 주제·관심 없음 초기화·본 기록 지우기). 추천 묶음·이어보기·내 취향 모두에 적용 (`web/src/lib/clip-prefs.ts`)
- 로그인 사용자: 본 기록·취향 설정을 계정에 저장하고 브라우저와 양쪽으로 합침 (사용자 DB v3 `watch_history`·`user_clip_prefs`, `web/src/components/auth/account-sync.tsx`). 탈퇴하면 삭제
- 시험: 운영 클립 DB 에서 숨김·관심 없음·덜 볼 주제 반영, 좋아하는 순간(레전드) 0→5개, 이유 10가지로 다양. 임시 Postgres + 위조 세션으로 브라우저↔계정 합치기·관심 없음 저장 확인
- 남은 것: 좋아요를 내 취향에 넣기(지금은 본 기록만 — 로그인 켜진 뒤), 내 취향을 홈에도

**키리누키 검색** ✅ 완료 (2026-11-13): 제목·버모아 요약·게임·사건·출연 버튜버 이름·키리누키 채널명, 띄어 쓴 낱말은 모두 포함, `#레전드` 같은 분류 태그. 사건 > 버튜버·게임 > 제목 순으로 위. `/clips?q=` 검색창, `/search` 에도 키리누키 결과 (`ClipRepo.searchClips`, `/api/clips?q=`)

수집 확대 (R1~R2 와 병행): 키리누키 채널 발견을 클립 설명의 원본 링크로 넓히기, 대상 버튜버 상위 200 → 500, `search.list` 하루 20회 → 필요 시 늘림(한도 100)

| 로그인 | 구글만. 이메일은 받지 않음(`openid profile`). 만 14세 미만 가입 불가 |
| 알림 | 웹 푸시. 방송 시작 15분 이내 감지 시에만, 같은 채널은 30분에 한 번 |
| 유튜브 재생 | `youtube.com/embed` (로그인 계정의 Premium 인식). 재생 버튼 전에는 불러오지 않음. 플레이어 수정·광고 차단 금지 |
| YouTube 키 | 서버(배포 PC `server\.env`)에만. 웹·저장소에 넣지 않음 |
| 중심 기능 | 키리누키 수집·분류·추천이 최우선 (2026-11-12). 이슈 타임라인은 지금 기능 유지, 추가 개발 안 함 (Claude 구독 사용량은 클립 분류 쪽에 우선) |
| 유튜브 전용 버튜버 | 해외 버튜버(홀로라이브 등)도 키리누키에 많이 나오므로 등록하되, LIVE 목록에는 한국어 버튜버만. 프로필에는 방송 통계를 만들지 않고 노래·클립 수만 (2026-11-13) |
| 노래 모음 | 공식 채널 영상 중 제목 표기로 고른 노래만. 조회수·인기 순위 없이 올린 날짜순 (YouTube 수치로 새 지표를 만들지 않음) (2026-11-13) |
| 백엔드 언어 | Node.js + TypeScript(Fastify) 유지, Rust 전환 안 함 (2026-11-12). 느린 곳은 언어가 아니라 SQLite 쿼리라 캐시·집계 테이블로 푼다. 배포 PC 자원 부족이 수치로 확인되거나 계산이 무거운 기능이 생기면 그 부분만 별도 프로그램으로 떼는 방향으로 재검토 |

## 5. 작업 규칙 (새 세션 필독)

- 사용자에게는 한국어로 답한다.
- 검증한 뒤에는 묻지 않고 `main` 에 커밋·푸시한다 (사용자 상시 허락). 커밋 메시지 끝에 `Co-Authored-By` 줄.
- **web**: Next.js 16 은 예전 지식과 다르다. 코드를 쓰기 전에 `web/node_modules/next/dist/docs/` 의 해당 가이드를 읽는다 (`web/AGENTS.md`).
- **배포 PC는 직접 조작할 수 없다.** 사용자가 RDP 로 실행할 스크립트·명령을 제공한다. 배포 PC 에서 코드를 고치게 하지 않는다. SSH 원격 관리는 제안하지 않는다.
- **PowerShell 스크립트**(`deploy/windows/`): Windows PowerShell 5.1 호환, **UTF-8 BOM + CRLF** 로 저장. 한글 바로 앞에 `$변수` 를 붙여 쓰지 말고 `-f` 포맷을 쓴다. 공통 함수는 `_common.ps1`(`Set-EnvValue`, `Get-EnvValue`, `Invoke-Native`, `Stop-ServerProcess` 등). `server\.env` 는 BOM 없는 UTF-8.
- **비밀 값**(토큰·키·시크릿·DB 비밀번호)은 출력하거나 커밋하지 않는다. 저장소는 공개다. 사용자에게도 채팅에 붙여넣지 말고 파일이나 각 서비스 화면에 직접 넣으라고 안내한다. 기본 PowerShell 창의 숨김 입력은 Ctrl+V 가 안 되므로 키 입력은 파일 방식을 우선한다.
- **Cloudflare**: 터널 `vmoa` 만 다룬다. 같은 계정의 다른 터널은 건드리지 않는다. 같은 터널을 두 PC 에서 동시에 실행하지 않는다.
- **새 서버 기능은 설정이 없으면 꺼지게** 만든다 (기존 예: `YOUTUBE_API_KEY`, `USER_DATABASE_URL`, VAPID 키, `ISSUES_ENABLED`, `DEBUTS_ENABLED`). 웹 로그인 UI 는 빌드 시 `NEXT_PUBLIC_AUTH_ENABLED` 로 결정된다.

## 6. 검증 방법 (이전 작업에서 쓴 것)

- 타입·린트: `server`·`web` 에서 `npx tsc --noEmit`, 바꾼 파일만 `npx eslint <파일>`
- 사용자 DB: `embedded-postgres` 로 임시 Postgres 를 띄우고 `USER_DATABASE_URL` 을 지정해 서버 실행
- 로그인이 필요한 웹 라우트: `next-auth/jwt` 의 `encode` 로 세션 쿠키를 만들어 `/api/me/*` 호출
- 화면·푸시: 헤드리스 Chrome(CDP)에 쿠키를 넣고 스크린샷. 실제 FCM 구독 → 발송 → 알림 표시까지 확인 가능
- 저장소 밖 시험 스크립트에서 top-level await 를 쓰면 `.mts` 로 만든다 (tsx)
- 배포 확인: `https://api.vmoa.live/health` 의 `version`, 웹은 `vercel ls`
- 입력마다 결과가 바뀌는 화면: `router.replace` 로 서버 컴포넌트를 다시 그리면 글자 입력 직후의 첫 이동이 다음 입력 때까지 반영되지 않는 문제가 있었음 (Next 16.2). 결과만 같은 출처 API 로 받아 바꾸고 주소는 `history.replaceState`/`pushState` 로 맞춘다 (`components/search/search-view.tsx`). 실제 입력 확인은 Orca 내장 브라우저 `type` 으로

## 7. 알려진 문제·정리 대상

- "주로 하는 방송"의 카테고리는 스냅샷이 있는 최근 7일 방송에서만 나온다 (일별 집계에 카테고리가 없음). 필요하면 `channel_daily` 에 마지막 카테고리 열을 추가
- SOOP 성인 방송 여부는 아직 확인하지 않음 (치지직만 썸네일 제외)
- 검색은 버모아가 방송을 한 번이라도 본 채널 + 유튜브 전용 버튜버만 나온다. 확정 목록(`vtuber_registry`)에만 있고 방송을 아직 못 본 치지직·SOOP 채널은 나오지 않음
- 유튜브 전용 버튜버 웹 수집은 치지직·SOOP 에 같은 이름의 버튜버가 있으면 넣지 않는다 (중복 프로필 방지). 짧은 흔한 이름(예: 2글자)은 다른 사람과 겹쳐 빠질 수 있으니 필요하면 `vtuber-add` 로 직접
- 노래 판정은 제목 표기 규칙이라 커버 MV 를 오리지널로 보는 경우가 드물게 있음 (`server/src/youtube/songs.ts` 의 규칙을 고치면 20일 안에 다시 확인하면서 반영)
- `web/src/components/theme-toggle.tsx` 에 예전부터 있던 lint 오류 (기능과 무관)
- `docs/deploy-fly.md`, `docs/deploy-railway.md`, `docs/backend-architecture.md` 는 예전 계획. 현재 배포는 Windows PC + Cloudflare Tunnel
