# 버모아 (VMOA) — 기획 · 개발 문서

> **한 줄 컨셉:** 흩어진 버튜버의 지금을, 한 화면에서.
> **문서 버전:** v0.1 (초안) · **작성일:** 2026-07-06 · **상태:** 기획 정리 중 · **수익 모델:** AdSense

- 가칭: **버모아(VMOA)** — "버튜버를 모아보다"
- 대안: `라이브덱 LiveDeck` · `뷔넥스트 VNEXT` · `V-DEX`
- 개발 코드네임: `Project VDEX`

---

## 01. 한눈에 — 무엇을 만드는가

치지직·SOOP·유튜브에 흩어져 방송하는 **한국 버튜버의 실시간 방송 현황·신규 데뷔·급상승·이슈**를 한 곳에 모아 매일 갱신하는 한국어 허브. 정적인 인물 DB가 아니라 **"지금 무슨 일이 일어나는가"**를 보여줘 반복 방문을 만드는 것이 목표.

**포지셔닝 한 줄:** 국내 인디·신인 버튜버에 특화된, 실시간 방송현황 + 데뷔·급상승·이슈를 자동으로 갱신하는 한국어 실시간 허브. 글로벌·대형은 Holodex/Streams Charts에 양보하고, 그들이 놓친 **치지직/SOOP 네이티브 + 이벤트성**을 노린다.

## 02. 배경 — 왜 지금, 왜 이 자리인가

| 기존 서비스 | 강점 | 빈틈 (= 우리 기회) |
|---|---|---|
| Holodex | 글로벌 라이브·멀티뷰 표준 | YouTube/Twitch만 — **치지직·SOOP 네이티브 미커버** |
| Streams Charts | 시청시간 기반 정밀 랭킹 | 유료·영어권 중심, 한국 인디 세분화 약함 |
| 소프트콘 뷰어십 | 한국 멀티플랫폼 뷰어십 | 순위 중심, 데뷔·이슈·큐레이션 약함 |
| 나의 작은 버튜버 | 중소 버튜버 인물 DB | **무수익·정체**, 실시간성 없음, 알림 종료 |
| 브니버스 | 한국판 홀로덱스 시도 | 사실상 정체 |

**벤치마크 — 덥덥미(wwme.kr):** 자동 수집(실시간 폴링) + 크라우드소싱의 하이브리드. 단, 크라우드소싱은 "실시간 값 입력"이 아니라 **"무엇을 추적 대상에 넣을지"를 제보받고 관리자가 검수**하는 데 한정. → 우리는 이 구조를 채택: **지표는 100% 자동, 사람은 대상 등록·이슈 큐레이션만** → 운영 부담 최소화.

## 03. 컨셉 — 3가지 차별점

순위·현황 자체는 레드오션. 차별화는 **트래픽이 도는 이벤트성**에 둔다. (= AdSense 트래픽 엔진)

1. **신규 데뷔 캘린더** — 오늘·이번 주 데뷔하는 버튜버를 자동 감지·정리. 기존 서비스가 가장 약한 영역.
2. **실시간 급상승** — 절대 시청자 수가 아니라 변화율 기반 "떡상 감지".
3. **이슈 타임라인** — 커뮤니티에 흩어진 사건·이슈를 한 곳에 아카이빙. 자체 텍스트 → AdSense 승인에도 유리.

**타깃 사용자**
- 코어 팬 — "내 최애가 지금 방송 중인지, 뭘 하는지" 반복 확인
- 신인 발굴형 시청자 — 데뷔·급상승으로 새 버튜버 발견
- 이슈 팔로워 — 씬 사건 따라잡기 (검색 유입 강함)

## 05. 데이터 소스 확보 전략

치지직이 데이터 확보의 중심축. Twitch는 한국 철수(2024.2)로 사실상 제외.

| 플랫폼 | 방송여부 | 시청자 | 라이브목록 | 과거통계 | 종합 판단 |
|---|---|---|---|---|---|
| **치지직** | 가능 | 가능 | 가능 | 자체축적 | **★ 최우선. 공식 OpenAPI + 비공식 다 열림** |
| **SOOP** | 가능 | 주의(지표해석) | 가능 | 불가 | 공식은 제휴심사 → 초기 비공식 의존 |
| **YouTube** | RSS+배치 | 가능 | quota 병목 | 저장허용 | 아카이브·구독자 보조 |
| **Twitch** | — | — | — | — | 제외 (한국 철수·24h 캐시·재배포 금지) |

**확보 방식 3단계 분류**
- 🟢 **직접 확보** — 치지직 공식 API(라이브·동접·팔로워·신규감지), YouTube 통계(장기저장 허용), Holodex 무료 API(해외)
- 🟡 **링크만** — Streams Charts·소프트콘(데이터 통합은 유료/ND 라이선스), Playboard·vling(API 없음) → 딥링크·출처표기
- 🟠 **회색지대** — SOOP·치지직 비공식 엔드포인트. 동작하나 차단 가능 → 공개 통계 한정 + 낮은 폴링 + 캐싱

**아키텍처를 강제하는 2가지 제약**
1. **과거 통계는 어느 API도 안 준다.** 치지직·SOOP 모두 시계열 미제공 → **1~5분 주기 폴링으로 자체 DB에 시계열을 쌓는 것이 필수 전제.**
2. **YouTube `search.list` 폴링 금지.** 채널 100개만 조회해도 하루 quota(10,000) 소진 → 반드시 **RSS 피드(무료)로 후보 발견 → `videos.list` 50개 배치(1 unit)로 확정** 조합.

## 06. 아키텍처 — 수집 파이프라인

`COLLECT → NORMALIZE → STORE → DETECT → SERVE`

1. **COLLECT** — 치지직/SOOP/YouTube 수집기가 주기적으로 라이브 목록·동접·프로필 폴링
2. **NORMALIZE** — 플랫폼별 응답을 공통 스키마(채널·라이브·지표)로 변환
3. **STORE** — 스냅샷을 시계열 DB에 축적. 원본 캐시는 단기 폐기
4. **DETECT** — 신규 채널·급상승·데뷔 이벤트 판정 → 이벤트 테이블 기록
5. **SERVE** — 캐시된 뷰를 프론트에 서빙 (현황·랭킹·데뷔·이슈)

**기술 스택 제안 (확정 아님 — 논의 대상)**

| 레이어 | 후보 | 이유 |
|---|---|---|
| 수집 스케줄러 | Node/TS 또는 Python + cron/queue | 기존 오픈소스(kimcore/chzzk=TS, python-chzzk) 재사용 |
| 데이터베이스 | PostgreSQL (+ 시계열 Timescale/파티셔닝) | 관계형 + 시계열 축적을 한 곳에서 |
| 캐시 | Redis | 현재 라이브 상태·핫 뷰 캐싱, 폴링 부하 완화 |
| 백엔드 API | Node(NestJS/Fastify) 또는 Python(FastAPI) | 수집기와 언어 통일 시 유지보수 유리 |
| 프론트 | Next.js (SSR/ISR) | SEO 필수(이슈·데뷔 검색유입) + AdSense 친화 |
| 호스팅 | VPS 또는 컨테이너(수집기 상주 필요) | 서버리스는 상시 폴링에 부적합 |

**SEO / AdSense 고려:** 단순 스크래핑 집계는 "thin content"로 AdSense 승인 거절 위험. 데이터 위에 자체 텍스트(데뷔 소개·이슈 정리·주간 요약)를 얹고, SSR로 검색 노출을 확보해야 트래픽·승인 양쪽에 유리.

## 07. 감지 로직

**신규 데뷔 감지**
- 발견 — 치지직 라이브 목록(`/open/v1/lives`) 폴링하며 **DB에 없는 channelId 등장 = 신규 후보** (YouTube quota 문제 없음)
- 판정 — 단일 신호 금지. **개설일 + 과거 이력 부재 + 데뷔 키워드("데뷔/첫방송/初配信/debut") + 구독자·동접 급증** 가중 결합
- 검수 — 완전 자동보다 커뮤니티 제보 + 사람 검수 혼합 (Holodex·HoloList 공통 패턴)

**급상승 감지**
- 원칙: 절대값이 아닌 변화율·속도 (대형 채널 편향 방지)
- 규모 보정 — 동일 팔로워 규모 코호트 내 백분위 순위 (SullyGnome 방식)
- 기법 — 이동평균 baseline 대비 z-score, 또는 EWMA 이중 창(단기 5분 vs 장기 24시간)
- 다지표 결합 — 시청자만 X. (동접 + 평균시청자 + 채팅량) 동반 상승 (소프트콘 20/40/40 참고)

## 08. 리스크 — 법적 · 약관 · 운영

- **YouTube** — 원본 30일 저장 한도, 단 통계 수치는 예외로 장기 보관 허용(랭킹 근거). 출처·브랜드 표기 필수
- **Holodex** — 무료·출처표기·**비경쟁** 조건. "복제 경쟁 서비스"로 보이면 위반 → 한국 특화 자체 가치 필수
- **소프트콘** — Basic도 CC BY-**ND**(변형금지) → 가공 집계엔 부적합. 상업 활용은 제휴 문의
- **비공식 API** — 예고 없이 변경·차단 가능. 공개 통계 한정 + 낮은 폴링 + 개인정보/저작물 저장 회피
- **팬덤 민감성** — "순위 박제"가 갈등 유발(덥덥미 사례). 버튜버는 더 민감 → vs 구도보다 정보·발견 톤으로 설계

## 09. 로드맵

- **0단계 (검증)** — 치지직 공식 API 키 발급 + 라이브 목록·동접 실측, 폴링→DB 축적 최소 프로토타입(스키마 검증)
- **1단계 (MVP)** — 치지직 실시간 허브: 방송 현황 + 신규 데뷔 감지 + 이슈 타임라인(P0 3종), SSR + 기본 SEO, AdSense 요건 충족
- **2단계 (확장)** — 축적 시계열로 랭킹·차트, SOOP 통합, 급상승 감지 엔진
- **3단계 (심화)** — 버튜버 통합 프로필, 멀티뷰, 알림, 커뮤니티 제보·검수 워크플로 고도화

## 부록 — 데이터 소스 상세 (조사 근거)

### 치지직 (CHZZK) — ★ 중심축
- 공식 개발자 포털: developers.chzzk.naver.com · 문서: chzzk.gitbook.io/chzzk · API: openapi.chzzk.naver.com
- 인증: Client(Client-Id/Secret) + OAuth 2.0. 스코프 5종(User/Channel/Category/Live/Chat)
- 주의: 90일 미사용 시 앱 자동 삭제. 429 rate limit.
- 공식 API로 라이브 목록/동접/팔로워 확보 가능. 과거 시계열은 미제공 → 자체 폴링 축적 필수.
- 비공식 API: `api.chzzk.naver.com/service/v1/...` (live-detail, home/lives, search 등) 무인증
- 오픈소스: [kimcore/chzzk](https://github.com/kimcore/chzzk)(TS), [python-chzzk](https://github.com/jonghwanhyeon/python-chzzk), [awesome-chzzk](https://github.com/dokdo2013/awesome-chzzk)

### SOOP (숲, 구 아프리카TV)
- 공식 Open API: developers.sooplive.co.kr — **개인 개발자 이용은 "준비 중", 제휴 심사 기반**(영업일 10일)
- 비공식: `live.afreecatv.com/afreeca/player_live_api.php`, `broad_list_api.php` (방송여부·시청자·목록)
- 버추얼 카테고리 존재. 국내 버튜버 생태계 활발(상반기 평균 방송수 273%↑)
- 구독자 수·과거 통계는 공식적으로 막힘 → 3rd party 병행
- 오픈소스: [zzik2/soop4j](https://github.com/zzik2/soop4j), yt-dlp/streamlink 추출기 참고

### YouTube Data API v3
- quota 하루 10,000 units. `search.list`=100 units(폴링 불가), `videos.list`/`channels.list`=1 unit(50개 배치)
- **현실적 설계: RSS 피드로 후보 발견 → videos.list 배치로 라이브·시청자 확정** (하루 ~6,000 units)
- `liveStreamingDetails.concurrentViewers`로 동접. 구독자 수는 유효숫자 3자리 내림(정밀 랭킹 부적합)
- 약관: 원본 30일 한도, **statistics 수치는 장기저장 예외 허용**. 출처 표기 필수. quota 증설 신청 가능(수주~수개월)

### Twitch — 제외
- 2024.2.27 한국 완전 철수. Helix `Get Streams`로 라이브·동접 가능하나 팔로워는 앱토큰 불가, VTuber 태그 필터 불가
- 약관: 24시간 캐시만, 재배포/공개DB 구축 금지 (매우 엄격)
